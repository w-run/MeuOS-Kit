> **M6 根因**（`projects/mcc/src/opt/rega.c` rega() 主循环）：
> QBE 上游只在 start 块**开头连续 regcpy** 段设置函数参数加载的 hint
> （`dst = copy PhysReg` → `sethint(dst, PhysReg)`）。但 mcc 前端会在
> start 块开头先发**栈参数加载**（`load S-x`，第 7+ 个参数），使该循环
> 在第一个非 regcpy 处 break，后续寄存器参数 copy 全部无 hint。
> 预分配时这些参数保存临时被任意分配到低编号 GPR（如 RDI），而其
> 真实位置在别处（如 RCX）→ `w[hint]` 记录**陈旧 hint**。循环内
> `RDI = add ...`（参数计算指令映射到 RDI）释放 RDI 时，hint move
> 误触发 `RCX = copy RDI`——但 RDI 此时不含该临时旧值（已被参数
> move 覆盖/含上次迭代值），破坏循环 live 参数值 → bzip2 blocksort
> 排序错、dash SIGSEGV。
>
> **修复**：sethint 循环改为扫描 start 块**所有** `Ocopy`（源物理寄存器
> 且目标 RTmp）的指令，不再因开头有 load 而中断。函数参数 copy
> 正确 hint 到物理源，预分配到位，w[] 不再记录陈旧 hint。
>
> **验证**：bzip2 纯 mcc roundtrip（文本/随机/2MB 全一致）；dash 纯
> mcc 构建运行（循环/函数/case/字符串扩展全对）；6 架构矩阵全 PASS；
> mcc 自举 PASS；arm/riscv64/i386/loongarch64 回归全过。

### mt/as+mt/ld 链接缺陷调查（#36，general-purpose-11，08-02）
> 复现：bzip2 8 个 .o（mcc -O2 + mt/as 编译），`mcc ... -o bzip2 ... -l:libc-meuos.a`
> 设 MT_AS/MT_LD 链接 → 压缩输出损坏（宿主 bzip2 无法解压，roundtrip 失败/挂死）。
>
> **定位结论**（同一批 .o，宿主 cc 链接 → 正常；mt/ld 链接 → 损坏）：
> - 单独 MT_AS（mt/as 汇编 + 宿主 cc 链接）→ PASS；单独 MT_LD（宿主 cc 汇编 + mt/ld）→ PASS
> - 两者同时设（mt/as 产物 → mt/ld）→ FAIL ⇒ **mt/ld 对 mt/as 产物的链接缺陷**
> - 47800b1（c73fd21 之前）即复现，c73fd21 后未解决 → 非审计引入
> - 症状：mtld 链接二进制 .text 与宿主链接存在 1993 字节差异（重定位应用不同）；
>   mtld 无 .symtab（mt/ld 一贯如此，简单程序也 0 符号，非根因）；.got 内容看似正常
> - bzip2 各 .o 含 R_X86_64_64（bzlib.o 16 个/bzip2.o 8 个，.rela.data 字符串指针表）
>   与大量 GOTPCREL/PC32/PLT32；最小 R_X86_64_64 与 GOTPCREL 用例 mt/ld 均正确
>   ⇒ 疑为 mt/ld 对 mt/as 产物中**特定组合/特定类型重定位**（或大 .data/.bss 布局）
>   处理错误，具体修复需 toolchain-reviewer 在 mt/ld 侧定位（任务 #36 已开）

> **补充调查（team-lead，08-02）**：同一 GNU 语法 .s 用 mt/as 与宿主 as 汇编产物对比——
> - mt/as 产物重定位 39 条 vs 宿主 29 条（多 10 条），且两者 .text 布局不同（mt/as 指令
>   编码更长：`cmp $imm32`(81) vs `cmp $imm8`(83)、`jle` 长跳转(0f8e) vs 短跳转(7e)，语义等价）
> - 关键差异：mt/as 对 `.Lstring.N`/`incs` 生成**符号级 PC32**（`R_X86_64_PC32 .Lstring.4 - 4`，
>   符号表有 LOCAL 符号值=偏移）；宿主 as 生成 **section 级**（`R_X86_64_PC32 .data + offset`）。
>   对 `stderr` 引用：mt/as 生成 `R_X86_64_GOTPCREL`(9)，宿主 as 生成 `R_X86_64_REX_GOTPCRELX`(42)。
> - 已排除的最小用例（mt/as+mt/ld 均 PASS）：符号级 PC32（lea msg(%rip)）、多字符串常量、
>   fprintf(stderr,...)（GOTPCREL）、R_X86_64_64 函数指针表 + 字符串指针表、`cmp $imm`/`jle`
>   循环逻辑。
> - 结论收窄：问题不是单一重定位类型，而是 mt/as 产物（符号级 local 符号重定位 + GOTPCREL(9) +
>   更长指令编码）在**较大 .o / 特定指令组合**下 mt/ld 链接出错；建议 toolchain-reviewer 用
>   blocksort-mtas2.o（GNU .s + mt/as 汇编，/tmp/bzdiag5/）作最小复现基座，对比 mt/ld 应用
>   重定位前后 .text，定位第一个语义错位点。

> **根因与修复（toolchain-reviewer，commit `c437d3b`，08-02）**：
> 实为 **mt/as x86_64 编码器 3 个 bug**（非 mt/ld 链接问题）。关键更正：mcc 的
> `mt_mode_enabled()` 要求 MT_AS 与 MT_LD **同时**设置才启用 mt 工具，此前"单独 MT_AS PASS"
> 实际走宿主 cc 汇编路径，误把 mt/as 排除在问题之外。改用 `mcc -S` + 分别用 mt/as 与宿主
> as 汇编 + 同一宿主 ld 链接确认 mt/as 产物损坏：
> 1. `test $imm, %r32` 被编成 `add`（`emit_binary_immediate` 硬编码 ADD opcode 0x80/0x81；
>    TEST 须用 0xF6/0xF7）→ blocksort 的 `testl $31,%eax` 被编成 addl，寄存器被污染。
> 2. movd 共享 movq 分支误设 REX.W → 32 位 MOVD 变 64 位 MOVQ（decompress 1700+ 条 movd）。
> 3. bin[] 表 strncmp 前缀匹配误捕获 SSE 助记符（`xorpd .Lfp5(%rip),%xmm2` 被当 `xor` 编成
>    `48 33 15`）→ andps/orps/cmpsd 同前缀指令风险。
> 修复：bin[] 后缀限 b/w/l/q（或空）+ `is_test` 参数选 0xF6/0xF7 + movd 分支不设 REX.W +
> 新增 XORPS/XORPD 内存操作数编码。
> **验证（team-lead 复核）**：bzip2 全 mt/as+mt/ld 管线 roundtrip 文本/随机 3MB/奇数长度
> 全部一致；meuos-toolchain make check 全绿。此缺陷为预先存在（非审计引入），现已根治。

## 08-02 严谨重新验证（/goal：qemu + 大型构建，确保无已知缺陷遗留）

### 新发现并修复的 arm 根本缺陷（`6199df9` mcc + `f36cd01` mt/as）

**arm 指针模型错误（LP64 vs ILP32）**：`sema/targ.c` 只对 i386 设 ILP32，arm 被当作 LP64
（指针/long = 8 字节 Kl）。而 armv7 是 ILP32、arm libc（gcc 构建）是 32 位 → 所有多指针
调用（strcpy/strncmp 等）把第 2 个指针编进第 1 个参数对的高字，调用 libc SIGSEGV。修复：
arm 与 i386 一样重设 long/ulong=4 字节。**此前 arm 矩阵只测整数/自写函数，未暴露**。

连带修复（arm 后端，在完整字符串/结构体/浮点/除法/6 参数/Kl 移位测试中逐个暴露）：
1. arm_isel：CAddr（`add r,$garr` 符号地址）与第一操作数常量拉入寄存器；sdiv/udiv 除数
   常量拉入（ARM 无立即数除法）。
2. arm_abi：非 vararg 5+ 参数栈传参（bzip2 mainGtU 6 参数）；栈参数 store 地址用 r12
   （防 rega 分配到 R0-R3 覆盖参数）。
3. arm_emit：间接调用（call S2/寄存器 → blx）；Osalloc 大小溢出为 slot；Kl 非常量移位
   软件循环（`1<<(signum-1)`）；neg → rsb。
4. arm_targ：R10（IP，隐式暂存）加入 reserved。
5. rega：dopm 物理占位消费计数；物理操作数自动占位；Ocall 参数寄存器占位（防调用栈
   参数 store 抢占 R0-R3）。
6. mt/as：sdiv/udiv/mls 操作数位域（Rn/Rm 换位 → 除法结果反）；movw/movt `:lower16:`
   字符集跳过误吞符号名（`remfn`→`mfn`、`r1` 撞寄存器）；ucomiss/ucomisd 内存源。
