### 发现的阻塞问题

以下 3 个问题阻塞了 `check-sysroot-static` target 和 `HOST_CC=mcc` 的直接自举：

#### B1: `check-sysroot-static` CFLAGS 缺失 -I 路径
- **文件**: `projects/mcc/Makefile` 第 223 行
- **症状**: `src/driver/cpu_detect.c:11:10: error: cannot find include file 'mt/target.h'`
- **原因**: `check-sysroot-static` 的 CFLAGS 包含 `-I$(abspath ../meuos-libc/include)` 和 `-I$(abspath ../meuos-sysroot/include)`，但缺少 `-I$(abspath ../meuos-toolchain/include)`，而 `cpu_detect.c` 需要 `mt/target.h`（来自 meuos-toolchain）
- **修复**: 添加 `-I$(abspath ../meuos-toolchain/include)`

#### B2: `detect_cpu_features` 缺少前向声明
- **文件**: `projects/mcc/src/driver/main.c` 第 479 行引用 `detect_cpu_features()`，但无前向声明
- **症状**: `src/driver/main.c:479:20: error: undeclared identifier: detect_cpu_features`
- **原因**: 函数定义在 `cpu_detect.c`，但没有任何头文件提供前向声明。GCC 通过隐式声明（返回 int）容忍，但 mcc 严格检查
- **修复**: 在 `src/driver/driver_internal.h` 中添加 `uint64_t detect_cpu_features(const char *arch);`

#### B3: `triple.c` 缺少 `#include <stdio.h>`
- **文件**: `projects/mcc/src/driver/triple.c` 使用 `snprintf()` 但未 include `<stdio.h>`
- **症状**: `src/driver/triple.c:72:2: error: undeclared identifier: snprintf`
- **修复**: 添加 `#include <stdio.h>` 到 triple.c

#### B4: MeuOS libc 缺少 `mprotect` 系统调用封装
- **文件**: `projects/sysroot/usr/lib/libc-meuos.a(dlfcn.o)` 引用 `mprotect`，但 MeuOS libc 未提供实现
- **症状**: `undefined reference to 'mprotect'`
- **原因**: `libmsys.a` 使用 overlay（需 `dlopen`/`dlsym`），`libc-meuos.a` 的 `dlfcn.o` 实现需要 `mprotect`（用于设置内存权限），但 `mprotect` syscall wrapper 未在 libc-meuos 中实现
- **影响**: 静态链接 mcc（通过 MeuOS sysroot）时触发，因为 `--nostdlib --static` 阻止了 glibc 提供 `mprotect`
- **修复**: 在 meuos-libc 中添加 `mprotect` syscall wrapper
