# mcc IR 重新设计与优化路线

> 基于 bzip2 纯工具链构建测试暴露的代码质量问题，重新审视 mcc 的 IR 设计和优化策略。
> 不是 QBE 的翻版，而是从结果出发、重新设计的优化体系。

---

## 一、审计：当前 IR 的问题

### 1.1 代码质量差距（bzip2 decompress.c）

| 指标 | gcc -O2 | mcc -O2 | 比例 |
|:-----|:-------:|:-------:|:----:|
| .text 段 | 11,203 B | 49,699 B | 4.4x |
| 栈帧 | 160 B | 3,976 B | 24.9x |
| mov 指令 | 1,081 | 7,098 | 6.6x |
| 栈操作指令 | 145 | 3,345 | 23x |

### 1.2 根因分析

| 问题 | 根因 | 影响 |
|:----|:-----|:----:|
| **寄存器分配** | spill pass 成本模型差，大量变量溢出 | 栈帧 25x、栈操作 23x |
| **指令选择** | omap 表 = 字符串模式匹配，单条格式串 | 无法利用 x86 寻址模式 |
| **缺少 pass** | 无 peephole / 无指令调度 / 无冗余消除 | 6.6x mov 指令 |
| **SSA 构造** | 基本块级，无全局值编号之外的跨块优化 | 冗余计算 |
| **常数传播** | 有 fold pass 但不充分 | 部分常量未折叠 |

## 二、设计原则

### 从结果出发，不是从 QBE 出发

```
QBE 的设计目标:   快速编译 + 简单代码生成（面向编译器初学者）
mcc 的设计目标:   代码质量接近 gcc -O1/O2 + 快速编译（面向自宿主）
```

| 维度 | QBE 原设计 | mcc 新要求 |
|:-----|:----------|:----------|
| 编译速度 | 优先 | 次优先（自宿主可接受 2x gcc 速度） |
| 代码质量 | 够用即可 | 接近 gcc -O1，目标 -O2 |
| 寄存器分配 | 线性扫描 | 图着色启发式 |
| 指令选择 | 单条格式串匹配 | 树匹配 / 多模式 |
| 跨块优化 | 基本块级 | 函数级全局优化 |

### 架构分层

```
源文件 → 前端的 AST → 中端 IR (MIR) → 后端的机器IR (LIR) → 汇编
                           ↓              ↓
                    平台无关优化      平台相关优化
                    (GVN/GCM/常量折叠)  (指令选择/寄存器分配/peephole)
```

当前架构的问题是 MIR 和 LIR 混在一起（同一个 `Fn` 结构，同一个 `Ins` 类型）。C++ 前端需要共享 MIR，但 LIR 可以不同。

## 三、MIR 设计（Medium IR — 中端）

### 3.1 结构

```
MIR 函数 (MFn):
  ├── MBlk[]    基本块
  ├── MVal[]    虚拟寄存器（SSA）
  ├── MVar[]    局部变量（含栈槽映射）
  └── MConst[]  常量池

MIR 指令 (MIns): 三地址码，每个指令至多 2 个源、1 个目标
  ├── 算术: add, sub, mul, div, mod, and, or, xor, shl, shr, sar
  ├── 内存: load, store, alloca
  ├── 控制: jmp, jnz, call, ret
  ├── 转换: cast, sext, zext, trunc
  └── 辅助: phi, copy, nop
```

### 3.2 与 QBE IR 的关键区别

| 特性 | QBE IR | mcc MIR |
|:-----|:-------|:--------|
| 类型系统 | 4 种 (w/l/s/d) | 完整 C 类型 (i8/i16/i32/i64/f32/f64/ptr) |
| 扩展性 | 固定结构 | 预留扩展字段，C++ 可加新指令 |
| 内存表示 | 混合类型/值 | 分离类型表 + 值表 |
| SSA | 隐式 | 显式 Phi 节点 |

### 3.3 MIR 优化管线

```
MIR 函数
  → CFG 构建 (fillcfg)          # 基本块连接关系
  → SSA 构造                    # 为每个 MVal 指定定义点
  → 常量折叠与传播 (fold)        # 编译时求值
  → 全局值编号 (GVN)             # 消除冗余计算
  → 全局代码移动 (GCM)           # 将循环不变代码外提
  → 死代码消除 (DCE)             # 删除无用 MIR 指令
  → 复制传播 (copy prop)         # 减少复制
  → 简化 (simplify)              # 代数简化 (x+0→x, x*1→x 等)
  → 内联 (inline)                # 小函数内联展开
  → 标量替换 (scalar replace)    # 将小聚合体拆散为独立虚拟寄存器
  → 常量合并 (constant merge)    # 相同常量的去重
```

## 四、LIR 设计（Low IR — 后端）

### 4.1 结构

```
LIR 函数 (LFn):
  ├── LBlk[]     基本块（映射自 MIR 的 MBlk）
  ├── LReg[]     物理寄存器分配
  ├── LSlot[]    栈槽（已溢出的虚拟寄存器）
  └── LIns[]     机器无关指令（指令选择后的结果）

LIR 指令 (LIns): 每条指令对应 0-1 条机器指令
  ├── mov, add, sub, ...  (与目标机器一一映射)
  ├── 目标寄存器已确定（由 rega 分配）
  └── 寻址模式已展开（base+index+displacement 形式）
```

### 4.2 与 QBE LIR 的关键区别

| 特性 | QBE | mcc LIR |
|:-----|:----|:--------|
| 指令选择 | omap 表（格式串匹配） | **树匹配**（指令选择器） |
| 寻址模式 | 发射时才处理 | LIR 级显式编码 |
| 溢出策略 | spill.c（固定优先级） | **图着色 + 溢出成本模型** |
| 并行移动 | rega.c dopm() | **并行移动优化器** |

### 4.3 LIR 优化管线

```
LIR 函数（指令选择后）
  → 树模式指令选择 (tiling)        # MIR → 机器指令
  → 寄存器分配 (rega)              # 图着色
  → 溢出插入 (spill)               # 按成本模型选择溢出变量
  → 冗余消除 (postra / peephole)   # slot→slot 复制消除
  → 指令调度 (scheduling)          # 乱序发射优化（可选）
  → 汇编发射
```

## 五、分阶段实施

### 阶段 1：当前（已完成/进行中）
| 任务 | 状态 |
|:-----|:----:|
| XMM15→RAX slot copy | ✅ |
| movs* 立即数修复 | ✅ |
| postra pass（冗余消除）| 🔄 提交中 |

### 阶段 2：优化现有管线（2-3 轮迭代）
| 任务 | 预期效果 |
|:-----|:---------|
| 改进 spill 成本模型 | 栈帧从 4000→1000 |
| 添加 peephole pass | mov 指令减少 30% |
| 改进 rega 并行移动 | xchg 从 102→10 |
| 消除 load-store 冗余对 | mov 指令减少 50% |

### 阶段 3：MIR/LIR 分离（架构级改造）
| 任务 | 说明 |
|:-----|:-----|
| MIR 定义和优化 | 类型系统 + SSA + 优化 pass |
| LIR 定义和指令选择 | 树匹配 + 寻址模式展开 |
| 寄存器分配重写 | 图着色替代线性扫描 |
| C++ 前端接入 MIR | mxx 共享 MIR 优化 |

### 阶段 4：高级优化（可选）
| 任务 | 说明 |
|:-----|:-----|
| 循环优化 | 循环不变外提、强度折减（GCM 已有基础） |
| 向量化 | auto-vectorization |
| 函数内联 | 自动内联决策 |
| LTO | 链接时优化 |
