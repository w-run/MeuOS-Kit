## 七、新增阻塞项（2026-07-30 补充验证发现）

> 通过全架构端到端管线测试和工具链交叉检查发现以下新增问题。

### 7.1 新增阻塞问题

#### P1 — nm/readelf ELF32 支持缺陷（新增）
- 工具链的 `nm` 和 `readelf` 无法正确处理 **i386 ELF32** 目标文件
- i386 crt1.o 的 `_start` 符号被 nm 显示为 `U`（未定义），host nm 正确显示为 `T`（文本段定义）
- 根因：ELF32 符号表解析路径有 bug，ELF64 无此问题
- 影响：i386 架构的符号查询/调试不可用

#### P1 — nm 不支持归档文件（.a）（新增）
- `nm libc-meuos.a` 输出 "not an ELF image"
- nm 没有实现遍历归档成员的逻辑，只能处理裸 .o 文件
- 影响：无法用 nm 查询静态库中的符号

#### P1 — ld ELF32 目标文件符号查找失败（新增）
- `ld --target=i386 ... crt1.o` 找不到 `_start` 符号
- 与 nm/readelf 的 ELF32 符号表解析 bug 同根因
- 影响：i386 架构无法完成正常的链接过程

## 八、复查验证（2026-07-30 二次实测）

> 对第三～七章的关键结论做了**独立复跑实测**，逐条核对是否可复现。
> 复查发现前几轮把「环境变量配置错误」误判成了「组件 bug」，此章为**权威修正**。

### 8.1 关键环境事实（推翻此前多个诊断的根因）

**`MEUOS_SYSROOT` 的正确取值是架构子目录，而非顶层 `sysroot/`。**

- sysroot 实际布局为**按架构分子目录**：
  `sysroot/<arch>/usr/include/` 与 `sysroot/<arch>/usr/lib/`
  （如 `sysroot/x86_64/usr/include/stdio.h`、`sysroot/i386/usr/lib/crt1.o`）。
- 本会话 shell 中 `MEUOS_SYSROOT=/workspace/MeuOS-Kit/sysroot`（**指向顶层，缺 arch 层**）。
- mcc 用 `sysrootpath(sysroot, "usr/include")` 拼路径，于是得到不存在的
  `sysroot/usr/include`，导致 `stdio.h`/`libc-meuos.a` 全部找不到。
- **纠正做法**：`MEUOS_SYSROOT=.../sysroot/x86_64`（或 `--sysroot=.../sysroot/x86_64`）。

实测对照：

| 条件 | `mcc hello.c` 链接 | `mcc -c <stdio.h>` |
|------|:---:|:---:|
| `MEUOS_SYSROOT=.../sysroot`（顶层，错误） | ❌ cannot find -lc-meuos | ❌ cannot find 'stdio.h' |
| `MEUOS_SYSROOT=.../sysroot/x86_64`（正确） | ✅ exit=0，可运行 | ✅ exit=0 |
| `--sysroot=.../sysroot/x86_64`（无 env） | ✅ exit=0 | ✅ exit=0 |
| 不设 `MEUOS_SYSROOT`（宿主模式） | ✅ exit=0 | —（依赖宿主头） |

**结论：mcc 的 sysroot 集成（include 搜索 + specs 链接）本身是正常的**，此前所谓「mcc sysroot 集成坏」纯属 `MEUOS_SYSROOT` 指向层级错误。

### 8.2 逐条复查结论（含对 0730 原判的修正）

| 编号 | 0730 原判 | 复查实测 | 修正判定 |
|:----:|------|------|:----:|
| P0-a | `mcc --specs=meuos` 编 C11 文件 **segfault** | `check-c11` 无 sysroot **15/15 PASS**；设正确 arch sysroot 后 specs 链接也 exit=0 | 🔴 **原判误判**：无 segfault，实为顶层 sysroot 路径错致链接/找头失败 |
| P0-b | `mcc --target=i386` 编 `memory.c` **segfault** | 设 `MEUOS_SYSROOT=.../sysroot/i386` 后 `--target=i386 -c memory.c` **exit=0**；不设时报 `cannot find 'stddef.h'`（缺头，非崩溃） | 🔴 **原判误判**：无 segfault，实为缺 arch sysroot 头文件 |
| P1-a | nm/readelf **ELF32 符号表解析 bug**（i386 crt1.o 的 `_start` 误判为 `U`） | 对真实 i386 ELF32 `crt1.o`（`Class: ELF32, Machine: Intel 80386`）：mt/nm 正确显示 `T _start`，mt/readelf 正确显示 `FUNC GLOBAL Ndx=1 _start`，与 host nm **一致** | 🟢 **原判不可复现**：ELF32 符号解析正常 |
| P1-b | ld ELF32 目标文件符号查找失败 | `ld -o out crt1.o`（无 `--target`）报 `unsupported input object`——是**缺 `--target=i386` 参数**，非符号表解析失败 | 🟡 **性质修正**：需显式 `--target`，非符号解析 bug |
| P1-c | nm 不支持归档文件 `.a` | `nm libc-meuos.a` → `not an ELF image` | ✅ **确认属实** |
| — | readelf 暂存改动 `< 16` → `< MT_ELF32_SYM_SIZE` | `MT_ELF32_SYM_SIZE == 16`，语义等价的 **no-op**；且该改动当前已不在暂存/工作树 | ✅ **确认为无效改动** |

### 8.3 复查新发现的真实问题（0730 未记录）

| 优先级 | 问题 | 证据 |
|:------:|------|------|
| **P1** | **meuos-compress `test/test.c` 引用未实现 API** | 引用 `MZ_CODEC_LZ77_HUF`、`struct mz_stream`、`mz_stream_init/feed/free`、`MZ_LEVEL_NORMAL`，头文件与源码中均无定义 → `make check` 编译失败。测试超前于实现 |
| **P2** | **meow `make check` 门禁路径写错** | Makefile 用 `cd .. && ./meow/$(BUILD)/meow ...`（期望顶层 `meow/`），源码实际在 `projects/meow/`。直接 `./projects/meow/build/meow build meow-smoke` → `✔ built` exit=0，**功能正常**，仅门禁脚本路径失效 |
| **P2** | **文档/环境：`MEUOS_SYSROOT` 语义需明确** | 应指向架构子目录 `sysroot/<arch>`，而非顶层 `sysroot/`。建议在 TIPS.md / bootstrap 说明中固化 |

### 8.4 复查后修正的建议优先级

1. **文档/环境**（最高性价比）：明确 `MEUOS_SYSROOT` 须指向 `sysroot/<arch>`；据此，0730 的两个 P0「segfault」应**降级/关闭**（不可复现）。
2. **meuos-compress**：对齐 `test.c` 与已实现 API（删除或补实 HUF/流式接口）。
3. **meow**：修 `Makefile` check 门禁路径 `./meow/` → `./projects/meow/`。
4. **nm `.a` 归档遍历**（P1-c，确认属实，仍需实现）。
5. **ld i386**：确认 `--target` 用法文档；`as` 非 x86_64 指令编码覆盖（P1，未在本轮复查范围）。

> **复查总评**：0730 审计的「组件实现度高、文档诚实」总基调成立；但其 **P0 两项 segfault 与 P1 ELF32 符号 bug 均为误判**，根因是 `MEUOS_SYSROOT` 指向层级错误这一环境问题。真实待办集中在 compress 测试对齐、meow 门禁路径、nm 归档支持三项。
