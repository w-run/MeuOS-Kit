### 6.3 关键发现

#### P0 — mcc 交叉编译后端 segfault（本次新增）
- `mcc --target=i386/aarch64/riscv64/loongarch64` 编译 `src/string/memory.c`（memcpy/memmove）时自身崩溃
- 这是所有非 x86_64 架构 libc 构建失败的唯一直接原因
- ARM 用 `arm-linux-gnu-gcc` 可绕过，非 mcc 后端 bug
- 与 `--specs=meuos` segfault 是同类问题，建议统一排查 irgen/emit 模块

#### P1 — as 指令编码器覆盖不全
- 非 x86_64 的 as 编码器仅实现 e2e 测试使用的指令子集
- mcc 生成的 `pushl/stp/sd/addi.d/hint` 等指令尚未实现编码
- as 无法从指令流自动推断目标架构，需显式 `--target=<arch>`

#### P2 — 环境缺失
- 无 QEMU 用户态模拟器，aarch64/riscv64/arm 运行时测试无法验证
- libdisasm 仅支持 x86_64 反汇编

## 七、新增阻塞项（2026-07-30 补充验证发现）

> 通过全架构端到端管线测试和工具链交叉检查发现以下新增问题。

### 7.1 新增阻塞问题

#### P1 — nm/readelf ELF32 支持缺陷（新增）
- 工具链的 `nm` 和 `readelf` 无法正确处理 **i386 ELF32** 目标文件
- i386 crt1.o 的 `_start` 符号被 nm 显示为 `U`（未定义），host nm 正确显示为 `T`（文本段定义）
- 根因：ELF32 符号表解析路径有 bug，ELF64 无此问题
- 影响：i386 架构的符号查询/调试不可用

#### P1 — nm 不支持归档文件（.a）（新增）
- `nm libc-meuos.a` 输出 "not an ELF image"
- nm 没有实现遍历归档成员的逻辑，只能处理裸 .o 文件
- 影响：无法用 nm 查询静态库中的符号

#### P1 — ld ELF32 目标文件符号查找失败（新增）
- `ld --target=i386 ... crt1.o` 找不到 `_start` 符号
- 与 nm/readelf 的 ELF32 符号表解析 bug 同根因
- 影响：i386 架构无法完成正常的链接过程

### 7.2 已排除的伪阻塞

| 问题 | 验证结果 | 说明 |
|------|---------|------|
| QEMU 不可用 | ❌ 假阳性 | env/qemu/ 下 4 个 qemu-user-static 齐全（aarch64/i386/loongarch64/riscv64） |
| meow 无构建产物 | ❌ 假阳性 | `projects/meow/build/meow` 存在（135KB） |
| x86_64 管线不通 | ❌ 假阳性 | `mcc → as → ld → run` 完整通过，exit=42 |
| mcc+libc 不工作 | ❌ 假阳性 | `--sysroot --specs=meuos` 编译运行通过 |
