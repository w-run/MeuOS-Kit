# MeuOS Kit 宏观任务树汇报

把整个领导/开发周期的推进，提炼为一张**骨干粒度的垂直任务树**，供大喵（项目所有者）以 token-plan 视角快速掌握全局。

## 核心原则（最关键）

- **宏观，不是微观**：树只到「目标 → 子目标」两级，**绝不展开到具体任务/commit/文件/行**。那些是 worker 的细活，不属于宏观汇报。
- **统帅视角**：leader 看的是方向对齐、进度、跨组件 integration、里程碑——不是任务细节。
- 意图是"一眼掌握全局"，不是"罗列所有做过的事"。

## 树图格式

两层垂直树：`🎯 终极愿景` → `🔷 目标`（若有多条）→ `├ 子目标 + 进度条 + 一句话说明`。

```
🎯 终极愿景：<一句话>
│
├── 🔷 <目标A>
│   ├ <子目标1>   ▓▓▓▓▓▓▓░░░  80%   一句话状态
│   ├ <子目标2>   ▓▓▓▓▓▓▓░░░  85%   ...
│   └ <子目标3>   ▓▓▓▓▓░░░░░  60%   ...
│
├── 🔷 <目标B>
│   └ ...
│
└── 🔷 待整合 / 当前 focus          ░░░░░░░░░░  —
    ├ <聚焦项1>
    └ <聚焦项2>
```

- **进度条**：`▓` 已完成、`░` 未完成；按百分比铺满 10 格（如 80% → `▓▓▓▓▓▓▓▓░░`）。
- **百分比**：leader 对"该子目标达成既定目标"的主观评估，非物理测度。估算逻辑：核心能力落地+验证=高值，edge/多架构/深面=拉低。
- **一句话说明**：每个子目标后附 ≤12 字的当前状态锚点（如"三编译器跑真实软件"、"阶段1-3 实用子集完整"）。

## 汇报节奏

- **里程碑/大喵提问时**：出完整树图。
- **子目标进度变化时**：只刷新受影响支线 + 一句宏观 delta（"系统 libc 多架构从 50→60%"）。
- 不在每次 worker 小提交后重画——那又退化回微观。

## 状态图例

- `▓` 完成并验证推送；`░` 未完成/登记后置
- 图例含：`[✅]` 完成、`[🔄]` 推进中/待协调、`[⏳]` 登记待办/后置（如需细分时用）

## 更新纪律

- 树图的百分比/状态从**当前 git 真实状态**推导（多分支 fetch 后核对），不只凭上次汇报记忆。
- 新方向（如大喵贴 AGENTS 目标清单）时，按其维度重构树图（可按目标/自举 Phase/架构矩阵/干流），而非硬套。
- 汇报后附 ≤2 个"当前 focus"待办，让大喵一眼看到下一步推进什么。

## 产出示例（示意）

```
🎯 全链路自举：取代 glibc 系统 libc + 自研 m++ + 真实软件跑通
├── 🔷 系统 libc     ▓▓▓▓▓▓▓▓░░  80%
│   ├ 运行时/入口契约  ▓▓▓▓▓▓▓▓▓░  90%   getauxval/libgcc/自动链
│   └ 多架构          ▓▓▓▓▓▓░░░░  60%   aarch64/riscv64 PASS；arm/loongarch 受限
├── 🔷 编译器 m++     ▓▓▓▓▓▓▓▓▓░  90%   异常阶段1-3 闭环
└── 🔷 待整合          ░░░░░░░░░░  —    异常基础进主门禁；inet_ntop 修通
```
