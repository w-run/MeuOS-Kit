# m++ 完整战役：核心规则与宏观目标

> 确立时间：2026-08-06
> 生效范围：整个 mxx-complete 长期分支周期

## 分支策略（永久分支，目标达成前不合并 main）

- 创建 **`feat/mxx-complete`** 长期主干特性分支，m++ C++ 全标准完成前**所有工作在此分支**，不合并 main
- 各 worker 从主干分出独立分支（`work/mcc-backend`、`work/mxx-cpp`、`work/libc-full`、`work/toolchain-deep`），避免交叉污染
- **m++ C++ 覆盖 98~23 完整前，仅允许提交到本分支的远程，不允许合并到 main**
- 完成后一次性合并主干分支到 main

## 质量铁律

- **禁止残留缺陷不处理**，哪怕是非阻塞问题。必须全部清零。
- **完全自举**：mcc 编译 mcc，端到端验证通过
- **端到端 PASS**：跨架构矩阵 6×9 全绿零 xfail
- **代码结构清晰**：重构/拆分大文件（cpp_parse.c 等）确保可维护
- **gate 必须做修复前失败验证**，证明 gate 真能抓住 bug

## 自主特性导向（不做缝合怪）

不满足于标准兼容，目标是「现代化编译工具」：

- **更多级别的编译优化**：-O0/-O1/-O2/-O3/-Os 精细化
- **更简化的编译体验**：一键构建、智能默认配置
- **更友好的内部组件联动**：mcc ↔ libmcc ↔ mt/toolchain 无缝协作
- **更现代化的错误反馈机制**：彩色诊断、建议提示、源码位置精度
- **更丰富的调试接口**：DWARF 调试信息完整、-g 开箱即用
- **更自由的编译产物与参数控制**：细粒度控制代码生成
- **更好的语言支持**：中/英双语诊断，用户可切换
- **不缝合**：自主实现、自主设计，非拼凑 GNU/LLVM 生态碎片

## C/C++ 标准覆盖

- **C 语言**：C90 ~ C23 完整覆盖
- **C++ 语言**：C++98/11/14/17/20/23 完整覆盖

## 工作纪律

- **文件级 git 提交**：`git add <文件>` + `git commit -- <路径>`，不整体 `git add .`
- **及时提交 + 文档更新**：避免网络波动导致工作中断，方便任务续接
- **多 subagent 使用临时工作分支**：各 agent 在独立 worktree/分支工作，不污染主工作区
- **单组件粒度提交信息**：`<组件>: <描述>`（如 `mcc: fix i386 DIV/REM`）
- **提交即推送远程**：每次提交后立即 `git push`

## 自主决策（禁止向用户提问）

- 目标未达成前**禁止向用户提问**
- **禁止终止目标**，除非用户主动介入
- 碰到技术障碍自主决策绕路或攻克，不请示
- 需要跨 worker 协作的通过 teammate 消息自行协调
