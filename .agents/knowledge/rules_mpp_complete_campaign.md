# m++ 完整战役：核心规则与宏观目标

> 确立时间：2026-08-06
> 生效范围：整个 mpp-complete 长期分支周期

## 分支策略（永久分支，目标达成前不合并 main）

- 创建 **`feat/mpp-complete`** 长期主干特性分支，m++ C++ 全标准完成前**所有工作在此分支**，不合并 main
- 各 worker 从主干分出独立分支（`work/mcc-backend`、`work/mpp-cpp`、`work/libc-full`、`work/toolchain-deep`），避免交叉污染
- **m++ C++ 覆盖 98~23 完整前，仅允许推送到当前工作分支的远程仓库，严禁合并到 main**
- 完成后一次性合并主干分支到 main
- 多 subagent 使用独立临时工作分支（如 `tmp/<worker>/<task>`），避免交叉污染

## 质量铁律

- **禁止残留缺陷不处理**，哪怕是非阻塞性问题（警告、冗余代码、潜在性能隐患、边界未覆盖等）。发现立即修复，不积累技术债务。
- **完全自举**：mcc 编译 mcc，端到端验证通过
- **端到端 PASS**：跨架构矩阵 6×9 全绿零 xfail
- **代码结构清晰**：模块分层明确（前端、中端优化、后端、运行时），接口整洁，注释充分
- **gate 必须做修复前失败验证**，证明 gate 真能抓住 bug

## 自主特性导向（不做缝合怪）

不满足于标准兼容，目标是「现代化编译工具」。基于对编译原理的深入理解自主设计，非简单堆砌开源组件：

- **更多级别的编译优化**：-O0/-O1/-O2/-O3/-Os/-Oz/-Ofast/Oprofile 等定制级别
- **更简化的编译体验**：智能参数默认值、渐进式构建、缓存加速、一键构建
- **更友好的内部组件联动**：词法/语法/语义/优化/后端各组件形成有机整体，mcc ↔ libmcc ↔ mt/toolchain 无缝协作
- **更现代化的错误反馈机制**：彩色、结构化、带修复建议的错误/警告信息，支持中/英文双语输出
- **更丰富的调试接口**：IR 可视化、优化日志、中间结果转储、DWARF 调试信息完整、-g 开箱即用
- **更自由的编译产物与参数控制**：允许精细控制指令集、对齐、节区布局、链接时优化
- **更好的语言支持**：目前中/英双语诊断，用户可切换；后续可扩展
- **不缝合**：自主实现、自主设计，非拼凑 GNU/LLVM 生态碎片

## C/C++ 标准覆盖

- **C 语言**：C90 ~ C23 完整覆盖
- **C++ 语言**：C++98/11/14/17/20/23 完整覆盖

## 工作纪律

- **文件级 git 提交**：每次提交只包含逻辑相关的文件变更，`git add <文件>` + `git commit -- <路径>`，不整体 `git add .`
- **高频提交 + 及时推送**：每完成一个可独立验证的小步（新增优化 pass、修复 bug 等）即提交并立即 `git push`，防止网络波动导致进度丢失
- **及时更新文档**：同步更新设计文档、使用说明和变更日志，方便任务中断后快速恢复
- **提交信息格式**：`<组件>: <描述>`，中文说明（如 `mcc: 修复 i386 DIV/REM 缺陷`）
- **多 subagent 使用临时工作分支**：各 agent 在独立 worktree/分支工作，不污染主工作区

## 自主决策（禁止向用户提问）

- 目标未达成前**禁止向用户提问**
- **禁止终止目标**，除非用户主动介入
- 碰到技术障碍自主决策绕路或攻克，不请示
- 需要跨 worker 协作的通过 teammate 消息自行协调
- 若遇到阻塞（依赖缺失、环境问题），自主寻找解决方案（如使用替代库、调整设计），并记录在案
- 所有决策与实现以**实现现代化、高性能、高可靠编译器**为最终衡量标准
