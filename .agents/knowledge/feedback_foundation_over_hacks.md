# 禁止 hack 绕行——必须加固根基

**核心原则**：发现编译器和基础库的根基能力缺陷时，直接修根基，不走 hack 绕行。

**Why:** 每一处 hack 都在积累技术债务，后续更多功能会反复撞同一堵墙。

**根基缺陷状态**：

1. **mcc 预处理器展开预算不足** — ✅ **已修复**（25711d68）。`expand()` 入口增加 `MAX_MACRO_DEPTH=256` 上限检查，超限时报 `E_SYNTAX` 错误。根因：`macrodepth` 只跟踪不限制。
2. **i386 后端缺专用 FP 暂存机制** — ⏳ 待修。pushl 加载 FP 常数破坏 alloca。应设计完整的 FP scratch 管理。
3. **m++ 急切实例化（D2）** — ⏳ 待修。模板成员函数全部急切实例化。应实现惰性实例化。
4. **跨架构 varargs 反复 SIGSEGV** — ⏳ 待修。每次只修表面。应做 va_list ABI 统一验证。

**地基大幅改动的上报纪律**：涉及大幅改动（影响多个功能、需要重构架构）时，必须先向 team-lead 上报实施计划（影响范围、方案选项、风险、实施步骤），获确认后再动手。不直接埋头猛改。pp-worker 注意：_Generic 预算修复如果涉及大幅改动 pp.c 必须先报计划。

**How to apply:**
- 根基缺陷影响 ≥2 个功能 → 直接修根基，禁止绕行
- 只影响 1 个测试点且修根基成本极高 → 允许临时绕行，但必须创建 TODO 排期修根基
- 绕行必须附带：`/* HACK: <原因> — FIXME: 修根基 <issue> */`
