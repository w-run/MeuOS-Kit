# 7z 容器格式兼容评估报告

> 2026-08-08 — fusion-worker

## 一、7z 格式概览

7z（7-Zip）是一种开放架构的归档格式，具有极强的压缩率，是当前通用归档格式中压缩率最高的之一。

**核心特性**：
- 开放架构：任何压缩/转换/加密方法均可插入
- 默认压缩方法 LZMA（改进型 LZ77 + 区间编码）
- 支持 LZMA2/PPMd/BZip2/Copy 多种编码器
- AES-256 强加密（SHA-256 密钥派生）
- 固实压缩（solid）：多文件拼成一个压缩流
- Unicode 文件名、大文件（至 160亿 GB）、分卷
- 文件头本身也用 LZMA 压缩

**魔数签名**（6 字节）：
```
37 7A BC AF 27 1C   (= "7z" + 0xBCAF271C)
```

## 二、格式结构复杂度

| 层级 | 组件 | 复杂度 |
|------|------|--------|
| 1 | SignatureHeader（32B 固定） | 低 |
| 2 | StartHeader（含主头偏移/大小） | 低 |
| 3 | **主头（压缩存储）**：含 PackedStreams/Coders/Folders/FileIndex | **高** |
| 4 | **LZMA 解码器** | **非常高** |

### 2.1 主头格式

7z 的主头不是简单二进制结构，而是一种类 ASN.1 的嵌套属性编码：`[属性ID][数据长度][数据]`。属性包括：
- `kEncodedHeader`：编码器定义（使用何种压缩方法、属性字节）
- `kFolder`：编解码器管道（coders 链，如 BCJ2+LZMA）
- `kStreamsInfo`：输入/输出流大小
- `kFilesInfo`：文件索引（名称、大小、CRC、属性、时间戳）

文件索引使用 B 树或顺序列表组织目录结构。

### 2.2 LZMA 算法复杂度

LZMA = LZ77 + 区间编码 + Markov 链状态机。

**解码器**：
- 11 种字面量上下文（基于匹配状态和位位置）
- 距离/长度/对齐位的多级上下文概率模型
- 区间编码器（50 行以内实现）
- 完整纯 C 实现约 2000 行，LZMA SDK 纯解压用约 5KB

**编码器**：
- 需建模器/字典管理/最优解析
- 复杂度远高于解码器，约 5000-8000 行

### 2.3 固实压缩

多文件共享一个 LZMA 压缩流，解压时需要按偏移切片。mz 的 solid 模式有对标但格式不同。

## 三、实现工作量估算

### 方案 A：完整实现（自研 LZMA 编解码）

| 模块 | 预估行数 | 难度 |
|------|----------|------|
| 7z 头解析（读主头/+文件索引） | 1500-2500 | 中 |
| LZMA 解码器 | 2000-3000 | 高 |
| LZMA 编码器（写） | 5000-8000 | 非常高 |
| 7z 头序列化（写） | 1500-2500 | 中 |
| 测试 + 兼容性验证 | 1000-2000 | 中 |
| **合计** | **11000-18000** | **极高** |

### 方案 B：管道模式（exec 7z CLI）

类似当前 zstd/bzip2 方案：
```
char cmd[4096];
snprintf(cmd, sizeof(cmd), "7z x -so %s 2>/dev/null", tmppath);
FILE *fp = popen(cmd, "r");
```

| 模块 | 行数 | 难度 |
|------|------|------|
| CLI 集成（mz_cli.c） | ~80-120 | 低 |
| **合计** | **~100** | **低** |

## 四、推荐意见

**L0 级建议：不实现。**

原因：
1. **格式极端复杂**：全阅读实现约 3500-5500 行（仅读），约 11000+ 行（读写）。这比 tar/gzip/zstd/bzip2 合集还大一个数量级。
2. **LZMA 算法本身**不是 MeuOS 生态需要的——mz 已有自有压缩引擎（LZ77 + Huffman/tANS/融合），再加一套 LZMA 是重复劳动。
3. **mz 格式已有对标特性**：固实压缩、加密、多文件、可执行过滤器（mz CLT + LZ77）。7z 的优势在互操作性而非技术必要性。
4. **互操作性需求低**：当前 MeuOS 工具链的交付物（sysroot .msys、编译器 .mz 包、归档 .mxa）都是自有格式，无 7z 消费场景。

**若未来出现真正的互操作性需求**，建议走管道模式（`popen("7z x -so ...")`），非实现模式。
