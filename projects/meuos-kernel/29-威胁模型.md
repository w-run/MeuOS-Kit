## 0. 一句话结论（先给答案）

MeuOS 的威胁模型**不是**「攻击者能否提权到 root」（因为没有 root），而是单一、清晰、可推理的两类目标：**（T-A）获取一个未被授予的 capability**，或 **（T-B）让最小 TCB 崩溃/停滞以制造 DoS**。由于权限 = 不可伪造的句柄 + rights 位图、且无任何身份特权逃生舱，攻击面被**结构性收敛**为「显式授予的句柄边界」——纵深防御因此可精确映射到 `07`（rights/pledge/unveil）、`10`（用户态驱动隔离）、`08`（兼容层翻译边界）、`17`（DBG_POKE 风险）、`20`（能力核心不变量证明）、`22`（否定式安全测试）六道防线，每类威胁都有唯一归口「挡点」。

## 1. ① 「应该是什么样」——以 capability 唯一模型定义攻击面

> 本节先抛开「别人如何建模威胁」（Linux 的提权链、Windows 的 EOP），从 MeuOS 自身约束出发，解构威胁模型**应该**长什么样。

### 1.1 起点：权限不是身份、权限是句柄

`07` §1–§4 已定：**权限 = 不可伪造的句柄（handle = capability）+ 随句柄走的 rights 位图**；无 root、无 uid=0 逃生舱、无 `CAP_SYS_ADMIN` 大杂烩。这一地基直接决定威胁模型的形状：

- 在 Linux 中，攻击者的最高价值是「成为 root / 拿到 CAP_SYS_ADMIN」，因为**身份即权力**——一旦身份被抬升，整片内核都可被操作。威胁模型是「提权链（LPE）」：找到任何一个root-only 路径的 bug，全盘失守。
- 在 MeuOS 中，不存在「身份抬升」。**攻击者持有的句柄集合是固定的、可枚举的、只能收窄不能扩张（I3 / `07` §4.5）**。因此：

  > **定义 1（攻击面边界）**：MeuOS 的攻击面 = 进程被显式授予的句柄集合 ∪ 进程可经 IPC 向已授权端点发起请求的入口 ∪ 内核 TCB 自身可被触发的崩溃点。
  > 一切「未授权访问」都等价于「试图获取一个不在自己句柄表中的 capability」或「试图越权使用已有句柄（rights 越界）」。

这与 `20` §2.1 的「capability 监视器是唯一裁决点、是 TCB 核心（00 A3）」互为表里：攻击面的**唯一授权闸口**就是能力监视器，守好它即守好绝大多数攻击面。

### 1.2 攻击者的两类终极目标

从定义 1 推出攻击者永恒的两类目标（其余一切都是其子集或手段）：

- **（T-A）capability 获取 / 越权使用**：让内核产生一个自己本不应持有的句柄，或让已有句柄的 rights 被放大，或借「受信任的中间人」间接获得越权效果（confused deputy）。
- **（T-B）TCB 崩溃 / 停滞（DoS）**：让最小 TCB（监视器、IPC 端点、低级 VM/调度）崩溃、死锁、或资源耗尽而停滞，使系统可用性归零。

> **关键推论**：由于权限不随身份走，**「攻破一个进程」的爆炸半径 = 该进程持有的句柄边界**，而非「整个系统」。这正是 capability 模型相对 root 模型的根本可防御性优势——威胁模型从「全或无」变成「局部、可枚举、可隔离」。T-A 与 T-B 的组合（如让用户态驱动崩溃后投毒重启）是本文重点关注的复合威胁。

### 1.3 威胁模型的「最小暴露」原则

从定义 1 进一步推演出 MeuOS 威胁模型的四条公理（贯穿全文）：

1. **默认全不可见**：进程只看见 spawn/unveil 显式注入的句柄与命名空间子树（A4 / C3）；未 reveal 即不在攻击面内。
2. **授权即攻击面**：每多授予一个句柄/right，就多开一个潜在 T-A 入口；因此最小权限（least privilege）不是「最佳实践」而是「攻击面最小化」的直接手段。
3. **TCB 即 DoS 面**：能被用户态直接触发的 TCB 崩溃点 = T-B 攻击面；TCB 越小、内存越安全，T-B 面越小。
4. **调试权 = 后门级面**：`DBG_POKE`（任意内存改写）一旦被滥用，等价于获得针对他人地址空间的任意写后门（`17` §1.1）——它本身就是最高危的「可被授予的 capability」，须单列建模。

## 2. ② 多系统参照对比表（威胁建模视角）

> 对照各系统的攻击面形态与威胁模型成熟度，取长补短、不缝合。成本/成熟度列仅供 ROI 比较。

| 系统 | 攻击面形态（威胁模型核心） | 威胁建模成熟度 | 对 MeuOS 的可借鉴点 | 与 MeuOS 现实的冲突 |
|---|---|---|---|---|
| **Linux** | 攻击面 = 内核整片 + 提权链（LPE）；root 万能；70+ syscall 全可触达；seccomp/SELinux 叠加仍难推理 | 大量 LPE 研究、KASLR/CFI 缓解，但模型松散（五套机制正交） | 「confused deputy / TOCTOU / 提权链」是反面教材，用来校验 capability 模型是否真堵住 | Linux 的「身份即权力」威胁模型与 MeuOS 不兼容，不能直接套用 |
| **Windows** | 攻击面 = EOP（提权）、VBS/HVCI（虚拟化隔离）、CFG（控制流完整性）、PatchGuard | 微软 SDL + 漏洞奖励 + 系统化缓解；有威胁模型但偏「缓解层堆叠」 | VBS/HVCI 的「把内核关键面放到更可信层」思想可借鉴为 TCB 加固参照；CFG 对应 ROP 缓解 | MeuOS 无 Hyper-V 式 VBS 基线；缓解靠 capability + Rust 而非 Hypervisor 隔离 |
| **macOS (XNU)** | 攻击面 = 沙箱逃逸史（AMFI / Page Sharing / 跨进程内存）、Mach 端口 cap 化 | 沙箱模型清晰、有 entitlement 体系；XNU 内核 bug 仍频发 | entitlement / `get-task-allow` 的「声明属性区分 dev/prod」（`17` §1.1）直接借鉴；沙箱逃逸史验证「capability 逃逸」是真实威胁类 | AMFI 仍寄生在 BSD 身份模型上；MeuOS 不保留身份层 |
| **Android** | 攻击面 = Stagefright（媒体解析）、Binder 攻击面、SELinux（每域策略）、treble 隔离 | 强威胁模型 + CTS/VTS 矩阵；媒体/驱动是高危面 | Binder 攻击面（transact 投毒）对应 MeuOS IPC 洪泛 / 派生树投毒；CTS 矩阵对应 `22` L4 | Android 仍有 uid/gid + SELinux 双模型；MeuOS 单一 capability 更简 |
| **塞班 (Symbian)** | 能力模型（capability model）攻击面小；权限即能力、粒度细 | 能力模型威胁面天然小，但生态小、文档少 | 证明「纯能力模型攻击面收敛」历史可行；验证本文 T-A 收敛结论 | 已淘汰，工程细节不可直接复用 |
| **ChromeOS / Fuchsia** | **默认无 root、capability 化使攻击面 = 显式授予的句柄；沙箱逃逸 = capability 逃逸**；有系统化 threat model 文档 | Fuchsia 有公开 security policy + threat model；handle/rights 模型与 MeuOS 同构 | **最贴近的范本**：威胁模型以「handle 能被如何误用」组织；Zircon exception bounded handle 对应 `17` 崩溃冻结；其 threat model 文档结构是本文结构参照 | Fuchsia 未做形式化验证；MeuOS 用 `20` 补证明层 |
| **seL4** | 攻击面 = TCB 边界（8700 行 C）；形式化验证消除整类漏洞；信息流安全证明 | 形式化威胁模型最严：证明「无未授权信息流」 | capability 核心不变量（I1–I7，`20`）直接对齐；攻击面只剩「验证未覆盖的非 TCB」 | 全量证明成本不可承受（`20` §7.4）；MeuOS 只证明极小核心 |
| **Capsicum (FreeBSD)** | 攻击面 = capability mode 下 fd 越界；沙箱逃逸 = 逃逸 capability mode | 有学术威胁分析（confused deputy 在 fd 模型下） | capability mode 逃逸案例对应 MeuOS「兼容层翻译错误导致越权」 | 仍寄生 UNIX 身份模型；MeuOS 不保留 |

**对比收口**：没有任何单一参照完美匹配 MeuOS。Fuchsia/塞班给了「默认无 root、攻击面 = 显式句柄」的范本；seL4 给了「攻击面收敛到 TCB 边界 + 形式化证明」的范本；Android Binder 给了「IPC/transact 攻击面」的实证；macOS/Chrome 给了「dev/prod 声明属性」与「沙箱逃逸」的实证。**MeuOS 应组合**：能力模型收敛攻击面（塞班/Fuchsia）+ TCB 最小 + 形式化证明核心不变量（seL4）+ IPC 攻击面实证（Android）+ 调试权声明属性（macOS）——非缝合怪：思想取长补短、实现自主研究。

> 本节给出 MeuOS 自身的威胁分类（非照搬 Linux LPE 分类）。每类威胁标注：攻击者手段、目标（T-A / T-B）、归口挡点文档、挡点机制。

### 3.1 分类总览表

| # | 威胁类 | 子类 | 攻击者目标 | 归口挡点（文档） | 挡点机制 |
|---|--------|------|-----------|------------------|----------|
| T1 | capability 逃逸 | 句柄伪造 / 表外句柄 | T-A | `07` §4.1 + `20` I7 | 句柄非 `Copy`、私有构造、表外无效（I7）；Rust 类型层 `PhantomData<Rights>` 防伪造 |

| T3 | 派生树投毒 | 越权 mint / 不受约束派生 | T-A | `07` §4.5 + `20` I5 | 受约束 mint（FS 服务自身 rights ∩ 客户端请求）；confused deputy 防护（I5） |

### 3.2 每类威胁的「应该是什么样」与挡点详述

#### T1 / T2 — capability 逃逸（句柄伪造、rights 越界）
- **攻击者手段**：构造一个表外句柄值欺骗内核（T1）；或持某句柄却执行其 rights 之外的操作（T2，如只读句柄尝试 `WRITE`/`EXECUTE`/`GRANT`）。
- **挡点**：`07` §4.1 的 `check_rights()` 是唯一裁决点；`20` I7（句柄不可伪造 / 表外无效）+ I3/I6（rights 只减不增）将其数学化。Rust 侧句柄**非 `Copy`、私有构造、borrow 防 UAF**（`20` Layer C），使伪造在类型层基本不可能。
- **fail-closed**：越权操作返回 `EPERM` 或触发 pledge 越界 `SIGABRT`（`07` §4.2）。

#### T3 / T4 — 派生树投毒与 confused deputy
- **攻击者手段**（T3）：让 FS/服务在 mint 派生句柄时发放超出自身 authority 的权限（不受约束的 mint → 派生树投毒）。（T4）：攻击者诱导一个持权服务代自己执行越权操作（经典 confused deputy，如经典的「编译器目录写」漏洞）。
- **挡点**：`20` I5（受约束 mint：`rights_issued = rights_service ∩ rights_client_requested`）是直接封堵；`00` C2 把密钥 unwrap 权绑定到文件句柄，使 FS 服务无法越权解密。这是 I3 在「服务端代理 mint」场景的特化。

#### T5 — 撤销时序竞态（TOCTOU）
- **攻击者手段**：在 `revoke` 与 in-flight IPC 消息 / `close` 之间存在竞态窗口，利用已撤销但未回收的派生句柄执行操作（`07` §5-4）。
- **挡点**：`20` I2（revoke 后传递闭包内的派生句柄全不可用）由 Layer A 证明；revoke 时序的并发交互由 `20` Layer B 的 TLA+ 模型检验穷尽（监督者重启状态机、IPC rendezvous、`00` A9）。原型期若仅显式 `close`（`07` §5-4 待决），挡点退化为「显式路径下 revoke 即失效」，全量派生链回收待 derivation tree 落地。

#### T6 / T7 — 调试权滥用（DBG_POKE / 崩溃冻结劫持）
- **攻击者手段**（T6）：获得 `DBG_POKE` 后改写任意目标进程内存/寄存器 = 针对他人地址空间的任意写后门，等价于「获取该进程全部句柄」。（T7）：持 `DBG_ATTACH` 的调试器借「崩溃冻结窗口」永久阻止监督者重启，使崩溃进程成为持久 DoS 面。
- **挡点**（T6）：`17` §3.1 裁决 `DBG_POKE` 单列、绝不默认、绝不随 `DBG_ATTACH` 自动获得、授予可审计、可 revoke（`07` §4.5 derivation tree）。这是对 `CAP_SYS_ADMIN` 教训的对照——把它**显式单列**正是避免「大杂烩」。（T7）：`17` §3.2 裁决监督者 `DBG_CRASHDUMP` 默认订阅、决策不可抑制；崩溃冻结**有界超时 + detach 自动释放**，自治重启不变量永不破坏（`00` A9）。

#### T8 — IPC 洪泛（资源耗尽 DoS）
- **攻击者手段**：无限创建 Channel/EventPort、向 Service Registry 注册大量名字、或向某端点狂发消息，耗尽内核队列/句柄表/服务名表，制造 T-B。
- **挡点**：每进程句柄数与消息队列深度计入 `07` §4.3 的 **Job 资源账本**（`00` A5）——`alloc(j, fds, n)` 超额即 `EAGAIN`（`20` I4）。服务名注册需持对应注册 capability（`05` §4.4），防名字表投毒/抢占。这与 `22` L0 单测「Job 账本不可超额」直接对应。

#### T9 — 驱动崩溃重启投毒
- **攻击者手段**：攻破一个用户态驱动（其只持自身设备能力），借崩溃-重启循环注入恶意驱动副本，或让驱动持续崩溃使设备不可用（T-B）；或借驱动持有的 MMIO/IRQ/DMA 能力越权触碰其他硬件（T-A）。
- **挡点**：`10` §4 双轨 + RS 式看门狗——用户态驱动**只持自身设备能力**（MMIO/IRQ/DMA/IO port，`10` §2.4/§4.6），越权触碰即被能力网关快速失败；崩溃由监督者策略重启（非驱动自决），重启经监督者注入最小能力集，防止「投毒副本」获得更大能力。内核态快速驱动经 HAL 宏访问，MMIO 经能力表校验（`10` §4.2）。

#### T10 — 兼容层翻译错误导致越权
- **攻击者手段**：Linux 二进制经兼容层发起 syscall，兼容层错误地把「本应 EPERM」的请求翻译成了过宽的内部 capability 操作（如把 `uid=0` 视图误映射为真实特权、把 `CAP_SYS_ADMIN` 整体授予）。
- **挡点**：`08` §3 铁律——root 是合成视图、不授予任何超越 capability 集的权限；兼容层**只消费 capability、不是发放方**（`08` §4.4 / `07` §4.6）。`00` C4 裁决默认**不允许** Linux 二进制绕过 pledge 默认沙箱；即使逃生通道也只是「该 Job capability 投影范围」显式扩大、记入 Job 账本、可撤销。翻译失败即 `ENOSYS`/`EPERM`（`08` §1.3），绝不悄悄降级。

#### T11 — TCB 内存安全（C/asm/i386 退化面）
- **攻击者手段**：利用 TCB 中 C/asm 部分（早期启动、i386 纯 C TCB、FFI 边界）的 UAF/溢出/悬垂指针，获取越权或制造崩溃。
- **挡点**：`02` §4 Rust TCB + `20` Layer C——安全关键组件用 Rust，编译期消除整类内存安全漏洞，把 seL4 花在 C 内存安全证明上的工作量「免费」获得。`20` §6.3 指出 i386 纯 C TCB 拿不到 Rust 保护，须额外上模型检验/fuzz 补偿（关联 `00` C6 / `22` L4 i386 纯 C 等价单测）。

#### T12 — 侧信道（DBG_PROFILE 跨 Job 采样）
- **攻击者手段**：持 `DBG_PROFILE` 跨 Job 采样 HW counter，借助 Spectre 类侧信道泄露跨进程数据（T-A 信息泄露）。
- **挡点**：`17` §5 原型期 `DBG_PROFILE` 限定同 Job 内；跨 Job 采样需更高权（待 `12` §7-8 评估）。这是 capability 模型「权限随句柄、显式授予」对侧信道的天然约束——采样权本身是一个可被 quota/right 限制的对象。

## 4. ④ 纵深防御映射（07 / 10 / 08 / 17 / 20 / 22 逐项对接）

## 5. ⑤ 自主结论 + 待决项

### 5.1 自主结论

1. **capability 唯一模型把「全或无」的提权威胁收敛为「局部、可枚举、可隔离」的句柄边界威胁**。威胁模型应从「攻击者能否成为 root」重写为「攻击者能否获取未授予的句柄（T-A）或让 TCB 崩溃（T-B）」——这是本文相对 Linux 威胁模型的根本翻转，也是 MeuOS 可防御性的来源。
2. **攻击面 = 显式授予的句柄集合**，因此最小权限（least privilege）不是最佳实践而是攻击面最小化手段；每多授一个句柄/right 即多开一个 T-A 入口。这与 `07` 的 least-privilege 默认成立、`20` 的「验证预算聚焦唯一裁决点」同源。
3. **纵深防御与验证纵深同构**：TCB 最小（主防线）→ Rust 类型（消除内存安全类）→ 形式化 I1–I7（证明逻辑不变量）→ `22` 否定式测试（证明越权必失败）。四层对应 `20` Layer A–D，威胁模型的「挡点」就是验证的「机检命题」。
4. **调试权是特殊高危面**：`DBG_POKE`（任意内存改写）是「可被授予的 capability 后门」，须单列、绝不默认、可审计可 revoke（`17`）。崩溃冻结窗口须有界，否则自治重启（系统自愈）被架空。
5. **兼容层是「翻译即授权」的高危边界**：唯一越权风险在于翻译错误地把 EPERM 请求放过；挡点在 `08` 铁律（root 合成视图、只消费不发放、翻译失败即 EPERM）+ `00` C4（默认不绕过沙箱）。
6. **用户态驱动把 T-A 爆炸半径锁在设备能力集内**：即使驱动被攻破，其可触达的硬件面 = 被授予的 MMIO/IRQ/DMA（`10`），且崩溃由监督者策略重启而非驱动自决，防止重启投毒。
7. **i386 纯 C 是纵深防御的已知弱化点**：其 TCB 拿不到 Rust 类型保护（`02` C2 / `00` C6），须以模型检验/fuzz 补偿（`20` §6.3 / `22` L4）——这是威胁模型必须显式标注的降级区。

|---|---|---|---|---|
